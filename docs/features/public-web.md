# Public web shell

## Purpose

The public shell presents the hosted product, explains its current limits and exposes legal baselines in crawlable HTML.

## Routes

All public routes live under the `app/(marketing)` route group, which wraps them with
`SiteHeader`/`SiteFooter`. The group segment does not appear in the URL.

| Route | Indexing | Purpose |
| --- | --- | --- |
| `/` | Index | Presentation landing page: hero, the gap it addresses, fit (`#para-quem`), six failure modes, principles (`#arquitetura`), flow (`#como-funciona`), surfaces (`#superficies`) and FAQ (`#perguntas`) |
| `/documentacao` | Index | Public, server-rendered guide for REST, remote MCP and progressive WebMCP |
| `/privacidade` | Index | Privacy notice, including data categories the authenticated UI was designed to treat |
| `/cookies` | Index | Current and planned cookie behavior, including the `__Host-` session cookie name |
| `/termos` | Index | Hosted-service terms and source-license boundaries |
| `/transparencia` | Index | Hosted V1 features, unavailable capabilities and operational limitations |
| `/robots.txt` | N/A | Crawl policy; disallows `/entrar`, `/cadastro`, `/recuperar-senha`, `/onboarding`, `/w` |
| `/sitemap.xml` | N/A | Public canonical route inventory (marketing routes only) |
| `/llms.txt` | N/A | Complementary, non-authoritative discovery file |

Private auth, onboarding and app routes are documented in
[`docs/features/app-web.md`](./app-web.md).

## Invariants

- Content is rendered on the server and is visible without client JavaScript. The scroll reveal
  (`components/reveal-on-scroll.tsx`) only engages once `data-js` is set on `<html>`, and it
  reveals everything at once under `prefers-reduced-motion`.
- Canonical host comes from `PUBLIC_WEB_URL`, defaulting to the approved production host
  `https://backlog.syntaxlab.com.br`.
- An empty or whitespace-only `PUBLIC_WEB_URL` also falls back to that production host, so
  metadata generation cannot construct an invalid URL from an empty container build argument.
- Every public page owns its canonical, Open Graph and Twitter metadata. Syntax Lab is the
  publisher, while Thales Gomes remains the author/creator. The landing page publishes
  `Organization`, `WebSite`, `SoftwareApplication` and `FAQPage` structured data; public
  documentation publishes `TechArticle` and breadcrumb data.
- Public pages share a 1200 × 630 Open Graph image with exact title, Syntax Lab signature and
  production domain. Its visual background comes from GPT Image 2; the reproducible HTML layer
  owns typography and brand text. Twitter uses `summary_large_image`.
- Above-the-fold landing content is immediately visible. Scroll reveal is limited to later
  sections so it cannot add an artificial delay to the hero LCP.
- `components/documentation/documentation-content.tsx` is the single documentation source for
  both `/documentacao` and the authenticated workspace guide. The public version uses explicit
  placeholders and never exposes a tenant identifier.
- Public documentation stays inside a boxed container with lateral breathing room, matching
  the landing page. The interactive API reference uses a documentation-style navigation/content
  layout with the existing Backlog Syntax palette. It is a separate API page, not the public guide.
- Syntax Lab branding appears on the landing page and login footer, with brand favicons and
  the neon dot after the Backlog wordmark. Login places the form on the right on desktop only;
  narrow-screen content order is preserved.
- The hosted first version is live and free, without an availability SLA. Landing copy and
  `/transparencia` must agree on shipped features and real limitations. Google login and
  transactional password-recovery email remain disabled; this visual revision does not change them.
- Landing imagery lives in `public/img` as a `<picture>` with the approved desktop JPEG
  and two mobile widths in WebP plus JPEG fallback. It is illustrative and labelled as
  generated by AI in the `alt` text.
- Optional cookies and analytics remain absent until consent behavior exists.
- Private app, onboarding and authentication routes are `noindex` and excluded from the sitemap.

## Hero art direction (September 2026)

The hero is full-bleed on desktop, using the user's approved 1921 × 916 JPEG and
the existing 1152px content column. The copy stays within its left half, with contrast protection
and the original headline at 85% of its former responsive size. The image uses
`object-fit: cover; object-position: center top`. Its charcoal palette stays stable
across themes; the rest of the site keeps its normal theme tokens.

Below 1024px, a separately composed mobile master (800 × 640) appears first in DOM
order as a top image band, fading into the section background, followed by the copy.
This is the mobile framing explicitly selected by the user, not a desktop crop.
One art-directed `picture`, media-matched preloads, explicit dimensions and WebP/JPEG
derivatives avoid duplicate downloads and image-driven layout shift. The active desktop asset
is `apps/web/public/img/hero-cover-desktop-preview.jpg`, preserved without recompression.
The `preview` filename does not mean staging. Source masters and derivative tooling remain
with the local implementation pending its code PR; see the [release baseline](../README.md#release-baseline).
The user approved the final JPEG and authorized its production release on September 6.

## Validation

```bash
pnpm --filter @backlog-syntax/web typecheck
pnpm --filter @backlog-syntax/web build
curl http://localhost:3000
curl http://localhost:3000/robots.txt
curl http://localhost:3000/documentacao
```

Inspect the rendered HTML at mobile and desktop widths. Verify a single H1, keyboard focus, no horizontal overflow, and real anchor links.
